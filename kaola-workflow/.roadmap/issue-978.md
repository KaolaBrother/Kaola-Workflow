All three are destroyed equally by the pre-change code, so these are residuals rather than regressions — filed because the guard is otherwise easy to read as absolute, and the CHANGELOG now says so in prose that a later reader may reasonably want closed. That bundle taught Step 0's clean-worktree guard to see untracked work: the probe widened from --untracked-files=no to -uall, and worktreeDirtRecords keeps every tracked record while filtering ?? records through isParkedLanePath(rel, []). The guard is sound in both directions — verified against the real sink CLI, refusing over a genuine file and over a self-referential symlink, while an ordinary lane-only run still completes and an over-broadening mutation refuses that ordinary run. These three shapes escape the classifier rather than the probe. (1) A filename containing backslashes — backslashes are legal in POSIX filenames, and isParkedLanePath normalises \ to / before testing, so a plain file literally named kaola-workflow\proj\x.md decodes correctly and then classifies as lane, exempted and destroyed. (2) An embedded git repository under a lane prefix — a nested worktree at, say, .kw/worktrees/nested/ is reported as one collapsed record even under -uall because git does not descend into another repository, the single record is exempted by its directory segment, and everything uncommitted inside it goes with the removal; this is the exception to the "one record per file" rationale that -uall was chosen for. (3) The legacy route removes the run's own .cache/ journal — the --sink route stages a best-effort rescue of <wt>/kaola-workflow/<project>/ before removal (sink-merge.js:2100-2130) so untracked .cache evidence survives there, but the legacy route has no equivalent and its rescue is try/catch best-effort covering only the own project. For whoever takes it: the fix must not break the two things the guard is balanced against — widening the exemption test breaks arm (f), since every ordinary run leaves untracked lane content and a bare widening refuses every sink, and reaching past --untracked-files into --ignored breaks arm (g), where nothing else in the 942-assertion suite catches that mutation; both arms are already in scripts/test-sink-merge.js. SPECIFY THE RESULT: the sink does not silently destroy uncommitted work in any of these three shapes — whether that is a stricter lane predicate, a descent into collapsed records, a rescue on the legacy route, or something else, is open.
