next_step: Observed during the #968 post-merge runtime refresh. install-all.sh:426-430 decides Codex currency with `if [[ "$installed" == "$tree" ]]` — pure version-string equality, then return 0, with no content comparison and no force path anywhere in the file. Measured after ./install-all.sh --forge=github --global --yes on a tree carrying new routing prose at an unchanged plugin version 7.8.0: claude, opencode and kimi surfaces all carried the new rule; the Codex cached SKILL at ~/.codex/plugins/cache/.../7.8.0/skills/kaola-workflow-next/SKILL.md still carried the RETIRED rule, with an mtime two days old, and the run reported "marketplace plugin already at 7.8.0" plus "codex PASS" and "all runtimes OK". Exactly one live Codex location was present (no standalone ~/.codex/skills shadow of these skills, one version directory), so nothing else was serving the new content. The file's own header comment states the intent the check misses — it says the wrapper owns the "is this runtime at HEAD" question and names the failure ("a tree bump keeps serving the previously-added version forever") while the code answers "is the runtime at the tree's declared VERSION". Consequence: Codex is the only one of four runtimes whose surfaces ship through a version-keyed cache, so it silently receives release-boundary changes only, while the installer asserts otherwise. Near-twin of #969 in consequence (a green report certifying stale consumer-facing surfaces) but a different mechanism on a different surface. SPECIFY THE RESULT: install-all does not report a runtime current when the content it serves differs from the tree, and a non-release change can reach Codex without a version bump. Unspecified whether that is a content hash, an unconditional re-add, a --force flag, or teaching the check to compare something other than the version string — and genuinely open whether refreshing a version-keyed cache in place is legitimate at all, or whether the honest fix is to REPORT the staleness and say a version bump is required, since a version directory whose contents silently change is its own hazard. The degraded arms just above the equality check already carry the vocabulary for reporting this (codex_degrade, "plugin convergence SKIPPED", "PENDING marketplace plugin upgrade").
