## Changed

- **ADR 0017 — the mission list — ships: the node/DAG executor is replaced by one file, four fields, three write moments (#877).** `docs/decisions/0017-the-mission-list.md` was accepted 2026-07-31; this lands the build sequence that decision required before deleting anything, and drops the "NOT BUILT" banner `CLAUDE.md` carried while the decision and the code disagreed. A run's coordination state — what to do, what went out, what came back — now lives in one file per run carrying `item` / `status` (`todo`\|`in-flight`\|`done`) / `dispatched` / `result`, written at three moments: created, dispatched, closed. `docs/mission-list.md` is the convention; it was authored and then proved carrying a real run — decompose, dispatch, close, and resume after a dispatch killed mid-flight — before any DAG machinery was touched, per the build sequence's own ordering principle (build and observe before deleting). **Concurrency carries no machinery at all**: no antichain sweep, no disjointness check, no serializer taxonomy, no evidence line, no fan-out cap. The frontier is `list minus closed minus in-flight`, visible by construction, and the orchestrator decides dispatch-or-do-it-yourself and at what width when it reaches an item, never earlier. An item carries no role, no write set, no dependency edge, no model, no cardinality — the existing control boundary (briefs carry evidence, never prescriptions) applies one level up and becomes moot rather than violated, because author and dispatcher are now the same agent.

- **The finalize door survives with its verdict traded for a report, per ADR 0016's own rule — delete the verdict, keep the measurement.** The door was never wholly DAG. Its validation arm was already ~95% plan-independent (`--release-check` was a shipped, working, plan-independent twin), so only the `validation_test_consumes` band needed relocating out of the retiring `plan-validator.js`. Its attribution arm — the sweep proving every changed path belongs to a declared write set — could not port as a verdict at all: the sweep's entire teeth are a declared write set authored *before* the work, and a free-text `result` field is not a path set; parsing one into a set would just re-invent the declaration ADR 0017 retires. It ports the way the sink already does under R3: emit the measurement (`git diff base...HEAD --name-only`, minus the allowband) beside the recorded per-item locators, and let the orchestrator reconcile — no verdict. Its post-dominance arm (the G1-G4 gate-coverage check over the ledger) has no list-form analogue and is deleted outright; nothing in the list form post-dominates anything.

- **The refusal count reaches zero.** ADR 0016's standing "keep merging; R3 survives permanently" does not port: the sink now reports what it found — content on the branch no record describes, a witness bound to different bytes, a merge that did not fast-forward — and the orchestrator owns the outcome: get the merge correct, resynchronize, or file a PR instead, then clean up after the sink. This is not "merge anyway and report" — the accountability for the branch ending up right moves from a door that used to say no to the orchestrator, which is the only party with the context to fix it. R1 (an unrecordable irreversible effect) was already unarmed for want of a fallback record location. R2 (a run clearing a human fence it never got answered) folds into the consent valve, which itself stops being durable machinery: the halt marker, the two `.cache/` journals (`consent-halts.json`, `consent-grants.json`) and `consentScopeDigest` retire along with the plan section that hosted the marker, and the valve becomes the orchestrator asking the user in conversation — a durable valve is only needed once a question must outlive the process that asked it, and until that is observed it stays on the watch list rather than the build list, alongside provenance stamps for stale/replayed evidence, CAS-with-lease for two honest writers on one file, honestly-labeled blends for co-open items, and a rescue ref per merge.

## Removed

- **BREAKING — the installed command surface collapses from five to three. `/kaola-workflow-adapt` and `/kaola-workflow-plan-run` are deleted, and so is `agents/workflow-planner.md` — the mandatory planner agent (#877, owner ruling 2026-07-31).** `/workflow-init` and `/kaola-workflow-finalize` keep their names; `/workflow-next` now creates and runs the mission list, absorbing what the plan-run loop and the re-plan/adapt entry point used to do. Planning is no longer a separate authored-and-frozen artifact, so there is nothing left for a dedicated planning agent to freeze — the orchestrator decomposes and dispatches at reach-time instead. **Vendored role agents are not retired**: `implementer`, `tdd-guide`, `code-reviewer`, `adversarial-verifier`, `security-reviewer` and the rest of the roster survive as dispatchable tools the orchestrator reaches for by name, exactly as it already does mid-run today; only the mandatory pre-assignment of a role to a frozen graph node goes. **This breaks a project holding a frozen `workflow-plan.md` mid-run**: once the DAG executor is gone there is no reader left for that file, and no migration path turns a frozen plan into a mission list. Finish any in-flight plan-run to completion — or discard the claim, whichever the run's own state supports — before upgrading past this change. A project that is claimed but has not yet frozen a plan is unaffected; its next `/workflow-next` starts a mission list instead.

- **The node/DAG executor and its plan grammar are retired**: roles and the role manifest, `depends_on`, declared write sets, the four-shape grammar and `select(<group>)`, post-dominance gates G1-G4, the antichain / `parallel_safe` disjointness sweep, the S1/S2/S3 serializer taxonomy and its evidence-line check, fan-out caps, expansion and re-expansion, the freeze chain, `plan_hash`, epochs and the re-plan CAS machinery, `ROLE_TOKEN_REGISTRY`, and the hollow-seed refusal. `scripts/kaola-workflow-adaptive-node.js`, `-plan-validator.js`, `-replan.js`, `-adaptive-handoff.js`, `-commit-node.js`, `-next-action.js`, `-task-mirror.js` and their per-edition twins go with it — recon inventoried these at roughly the scale the ADR itself estimated, ~35k canonical lines of node-execution core, well over 100k more across the four editions, plus `docs/plan-run-cards/`'s ten wholly-DAG reference files. `scripts/kaola-workflow-adaptive-schema.js`, the cross-edition byte-identical anchor, is **not** deleted — recon split it line-by-line rather than assuming it was DAG by association: roughly 19% (crypto/JSON helpers, the atomic-write primitive, worktree topology, the durable-artifact registry, envelope emitters) survives untouched in the same file, roughly 73% (the plan grammar, the epoch/re-plan machinery, the reviewer-contract v2 engine, the refusal kernel) is deleted, and the remainder — the model-tier/dispatch-effort tables and the project scheduler lock — was a values call rather than a mechanical one, resolved by the ruling above (tables survive stripped of their role-keying; the lock retires to the watch list). Tests are deleted with their mechanism, never repaired ahead of it. The integration suite and its mixed siblings (`test-claim-hardening.js`, `test-gap-sweep.js`, `test-sink-merge.js`, `test-run-chains.js`, `test-refusal-route-sweep.js`, `test-interior-gate-freshness.js`, `test-barrier-base-integrity.js`) are triaged scenario by scenario rather than deleted whole, because they also cover claim/finalize/sink/release behaviour that survives.

- **Named accepted losses, so they are not discovered as surprises later.** The `upstream_read` consumed-proof — the nonce-bound check that a node actually read its predecessor's evidence before writing over it — has no list-form analogue that is not a role/edge system in disguise; nothing will detect an item that ignored a predecessor's findings, and the mission list does not pretend otherwise. Per-role evidence richness goes with `ROLE_TOKEN_REGISTRY` and the role manifest. Early scope-violation detection goes with declared write sets: a violation is now noticed when a reader looks, not one node later — the same trade ADR 0016 already made at the finalize door, which ADR 0017 now makes everywhere.
