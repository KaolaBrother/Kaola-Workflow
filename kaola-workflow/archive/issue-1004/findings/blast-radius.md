## D. The third shape — fill-if-empty

### D1. The function, verbatim (`kaola-workflow-claim.js:3940–3958`, identical in all four copies)

```js
function appendSummarySection(projectDir, heading, lines, replace) {
  try {
    const p = path.join(projectDir, 'finalization-summary.md');
    let s = '';
    try { s = fs.readFileSync(p, 'utf8'); } catch (_) { /* create-if-absent */ }
    const existing = s.match(new RegExp('^' + heading.replace(/[.*+?^${}()|[\]\\]/g, '\\$&') + '$', 'm'));
    if (existing) {
      if (!replace) return false;
      // Cut the heading through to the next `## ` heading (never a `### ` sub-heading, which is
      // three hashes and so cannot match) or to end of file.
      const after = s.indexOf('\n## ', existing.index + heading.length);
      s = s.slice(0, existing.index) + (after < 0 ? '' : s.slice(after + 1));
      if (!s.trim()) s = '';
    }
    const block = [heading, ''].concat(lines).join('\n') + '\n';
    writeFile(p, s ? (s.trimEnd() + '\n\n' + block) : block);
    return true;
  } catch (_) { return false; }
}
```

### D2. Is the middle path mechanically available? **Yes, with no new parsing.**

The function already computes both endpoints of the section body — it just computes the second one
**inside** the `replace` branch, one line after the early return:

- start of body = `existing.index + heading.length`
- end of body = `after` = `s.indexOf('\n## ', existing.index + heading.length)`, or EOF when `after < 0`

Emptiness is therefore
`s.slice(existing.index + heading.length, after < 0 ? s.length : after).trim() === ''`.
**The only mechanical change required is hoisting the existing `after` computation above the
`if (!replace) return false;` line.** No new regex, no new scan, no second read, no new argument.

### D3. What "empty" means in the actual file format

The delimiter grammar the function already commits to:
- **A section ends at the next line-initial `## ` or at EOF** — the 4-character literal `'\n## '`.
- **`### ` sub-headings do NOT terminate a section** (4th char is `#`, not a space). Load-bearing:
  the findings flush writes `### <type>` bodies under `## Finalize Findings` (`:4262`).
- **Headings match exactly, alone on the line** — `## Final Validation` does not match
  `^## Validation$`, which is why the `test-sink-merge.js` fixtures are inert here.

Given that grammar, both field shapes parse as empty:
1. **The Step 6 template as written** — three consecutive heading lines, no blank between: `'\n## '`
   matches at the offset immediately after `## Validation`; body slice is `""`.
2. **The shape orchestrators actually produce** (verified `archive/bundle-992-993-994/…:74–80`) —
   heading, blank line, next heading: match lands on the blank line's `\n`; body slice is `"\n"`;
   `.trim()` → `""`.
3. **Last heading in the file** — `after < 0`, body `""` or `"\n"`; `.trim()` → `""`.

So `.trim() === ''` is the natural predicate, and it treats "heading followed only by blank lines" as
empty. That is a **choice**, not forced: a stricter `=== '\n'` predicate would classify the
blank-line form as non-empty and miss all 15 real archive cases.

### D4. Known edge cases of the existing grammar (pre-existing; none introduced by any shape)

- **A `## ` line inside a fenced code block terminates the slice early.** Archived summaries do carry
  fences. No archived instance observed under one of the three headings.
- **CRLF** — `$` under `/m` matches before `\n`; a preceding `\r` blocks the exact match, so today
  that produces a *duplicate* heading (append branch), not a decline. Unaffected by any shape.
- **Trailing whitespace on the heading** — same duplicate outcome. The Step 6 prose already warns
  about the analogous case for `## Run gaps` (skeleton `:242`).
- **`s.match()` returns the FIRST occurrence only.**
- **Shape 1 relocates the section** — `replace` cuts and the block is appended at the tail (`:3955`),
  so a pre-created `## Validation` at line 74 comes back at the bottom, after `## Status: ARCHIVED
  AFTER FINAL GIT GATE`. That is the layout `bundle-1001-1002` already has organically.

### D5. Signalling — what the function can and cannot report today

- `appendSummarySection` returns `false` for **both** "declined because the heading exists" **and**
  "threw" (outer `catch` `:3957`). Indistinguishable to a caller.
- All three `persist*` writers return that boolean (`:3976, 3988, 4057`), and **all three call sites
  discard it** (`:4457–4459`).
- `recordFinalizeFinding` (`:4248–4250`) and `flushFinalizeFindings` (`:4252–4267`) are declared at
  `cmdFinalize` scope (`:4174`), i.e. **in scope at `:4457–4459`**. A finding recorded there would be
  flushed later, because `flushFinalizeFindings` early-returns while `result.dest` is unset (`:4257`)
  and the accumulator is restated in full on every flush (`replace=true`, `:4266`). **The machinery to
  report a declined durable write already exists and is already in scope; nothing is wired to it.**
- `finalizeTx` carries `residue_stage`, `archive_stage`, `finalize_commit`, `findings`
  (`:4210–4233`, `:4256`). There is no field for the durable-write outcome.
