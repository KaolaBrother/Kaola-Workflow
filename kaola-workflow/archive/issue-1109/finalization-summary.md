# Finalization Summary — issue #1109

## Delivered

A Codex reinstall no longer reorders `~/.codex/hooks.json`, so Codex's position-keyed hook trust
survives it for both Kaola-Workflow's hook and foreign hooks.

Root cause: `mergeHooks()` stripped every `kaola-workflow:`-prefixed entry and appended the managed
entries at the end of each event array. When another tool's hook followed ours, a reinstall moved
ours behind it. Codex records trust as `hooks.state."<hooks.json>:<event>:<i>:<j>".trusted_hash`, so
the swap invalidated the stored hash of both entries, and the installer reported `updated` although
no managed content changed.

Fix: under every event, a managed-prefixed entry is replaced at its current index by the template
entry with the same `id`; it is dropped when the template no longer carries that id (or it is a
later duplicate). Only managed entries not already replaced in place are appended. The `id`-less
guard is kept. `updateHooks()` (including #1108's backup fix) and the `config.toml` `hooks.state`
tables are untouched.
