# Finalization — Summary: bundle-937-938-939

Three claim-artifact issues left behind by the #936 run, settled in one run because they share one

## Delivered

**#937 — a mis-cased `--project` half-finished a run.** CONFIRMED by drive, and wider than filed.
The issue's own stated mechanism was **REFUTED**: `activeByProject`'s strict `===` is a real
case-fragility but is *not* on the causal path — a counterfactual leg with the folder still
unresolvable but the marker spelled the operator's way deleted both markers successfully. The actual
defect is that `cmdFinalize` and the sink pass the operator-supplied `args.project` into a marker
matched by exact substring, instead of the resolved on-disk name. Also wider than filed in two ways:
it is **not keep-open-specific** (close mode misses identically), and the sink additionally
**published corruption** — because git's index is case-sensitive while APFS is not, the archive move
found the content but the removal pathspec matched nothing, so a fresh clone of the remote carried
`archive/Issue-X/` *and* the never-removed live `kaola-workflow/issue-x/`, with main left dirty,
all under `result: ok, status: sinked`, exit 0.

Fixed by resolving the slug **once, before anything is composed from it**, so all ~40 downstream
reads see the resolved spelling — one resolution rather than five patched call sites, which is what
makes the archive-naming and pathspec symptoms fall out too. Reported as `resolved_project_note`,
absent when the spelling was already exact. Owner-ruled resolve-and-report; refusal declined.

**#938 — an offline finalize reported success having released nothing.** CONFIRMED. Zero forge
calls, both artifacts surviving on every member, in both lanes. One correction to the issue: the
**label** is the first and sufficient blocker and has **no expiry**, short-circuiting the marker
probe entirely — proven by a 2×2 isolation whose aged-marker cell acquires and whose both-absent
control acquires. Fixed with the typed finding `claim_release_skipped_offline` through the existing
`recordFinalizeFinding` channel, worded **conditionally** because nothing local records whether the
claim was posted online. Report, not gate: `closure_invariants.ok` stays `true`. A "make it violate"
fix was measured to be a contract change reddening two named walkthrough pins, and was not taken.

**#939 — CLOSED WITH NO CODE on its own question.** Answered NO by seven driven legs. Still exactly
six refusal doors; all six fire with the mainline untouched, none performs a mutating forge call,
and all precede the merge by construction — after an archive refusal *both* sink forms refuse to
merge. The most hostile ordering (merged and pushed by hand, then door 6 fires) does not qualify:
unreachable from inside the workflow, and live run state exists in three places. Three recovery
paths were driven green. The only residual was **routing**, and that is what changed: each of the six
doors now names `release` as the exit, from the main root.

**Adjacent, owner-approved:** a blocked re-claim now names *which* artifact blocked it, across six
emitters in four editions — the undiscriminating message is what left #936's reporter unable to
diagnose their own symptom.

**Owner rulings recorded so they are not re-litigated:** #938 → typed finding, conditional, no
`remote_claim` token; #937 → resolve-and-report, refusal declined; #937 Direction 2 and its two
adjacent observations → watch-list, no code; slug resolution → **uniform across filesystems**, the
case-sensitive refusal deliberately not preserved.
