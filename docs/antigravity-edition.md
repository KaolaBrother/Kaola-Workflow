# Antigravity edition

Kaola-Workflow delivers its workflow commands to the Antigravity CLI (`agy`) the Antigravity-native
way: directory-form skills under `~/.gemini/config/skills/<name>/SKILL.md` and a managed
machine-global contract carrier at `~/.gemini/config/AGENTS.md`. The support boundary is the
measured local CLI (agy 1.4.7, issue #1122); App, IDE, and cloud hosts are out of scope until
separately measured.

## Measured roots (agy 1.4.7, 2026-10-26)

agy separates two directories, and only the first is a supported install destination:

- `~/.gemini/config` — the global customization root (agy's own shipped `agy-customizations`
  guide): direct standalone `AGENTS.md`/`GEMINI.md`, `skills/`, and Kaola support scripts under
  `kaola-workflow/scripts`. This is where the installer writes.
- `~/.gemini/antigravity-cli` — CLI settings and builtins. The installer never writes here.

The public docs' skills table names `~/.gemini/antigravity-cli/skills`; the measured loader on 1.4.7
discovers global skills from `~/.gemini/config/skills` (probe-verified below). KW supports the
measured root only and never dual-installs to hide the discrepancy.

## Probe results (MacBook, issue #1122)

- **Global carrier (M1, PASS).** A fresh `agy --print` process in an unrelated `git init` fixture,
  with tools disallowed, quoted the exact speculative-robustness sentence carried only by the
  managed `~/.gemini/config/AGENTS.md` region: the carrier is automatically loaded into fresh
  sessions.
- **Project instructions (M2, PASS).** Unique-token rules in a project `AGENTS.md` and, separately,
  a project `GEMINI.md` were each obeyed by fresh sessions in that project. Both project file names
  load.
- **Skills (M3, PASS).** The global skills catalog in an unrelated workspace listed
  `kaola-workflow-finalize`, `workflow-init`, and `workflow-next` beside a probe fixture at
  `~/.gemini/config/skills`, and native `/probe-fixture-skill` slash invocation returned the
  fixture's exact reply token.
- **Reload boundary (M4).** Fresh-process reread is measured: every probe above was a new `agy`
  process reading current bytes. Same-session hot reload and post-compaction carrier/skill
  retention are **not measured**. Recovery from a compacted session is explicit skill re-invocation
  (for example `/workflow-next`), which resumes from the durable mission ledger and workflow state;
  no automatic compact recovery is claimed and no hooks are installed.

## Install, check, uninstall

```sh
./install-antigravity.sh --global --yes --forge=github   # default: global scope
./install-antigravity.sh --project[=DIR] --forge=gitlab  # project skills under DIR/.agents
./install-antigravity.sh --global --check                # verify owned artifacts only
./install-antigravity.sh --global --uninstall            # remove only Kaola-deployed artifacts
node scripts/kaola-workflow-global-contract.js check --runtime antigravity --json
```

`--check` compares only Kaola-owned skills and support scripts; unrelated user skills never
drift-fail it. A missing or drifted Kaola skill does. Uninstall removes skills by rendered
directory name and support scripts by manifest name, strips this runtime's own managed region
through its per-target global-contract record (an owner-edited carrier is refused and left in
place), and releases the shared `~/.config/kaola-workflow` reference. No root-override environment
variable exists for this runtime: none is measured, and tests relocate installs by overriding
`HOME`, which the installer and the global-contract CLI resolve identically.

## Forge variants and project scope

`--forge=github|gitlab|gitea` selects the workflow prose and support scripts (generated by
`scripts/sync-antigravity-edition.js` from the same routing surfaces every edition ships). The
shared global support root holds the selected forge's scripts; the installer copies them and
does **not** delete another forge's renamed scripts. The skills entry is the last-installed forge's
render, so simultaneous different-forge global installs are not independent. Project scope
writes skills under `<DIR>/.agents/skills/<name>/SKILL.md` and leaves the machine-global carrier
untouched.

## Boundaries

- The rendered skills keep the common runtime dispatch contract **inline** and replace only the
  adapter-facts region; Antigravity is not an always-loaded-carrier recovery runtime in the
  routing engine.
- No Kaola role profiles, no hooks, no model bindings ([ADR 0029](decisions/0029-native-subagents-only.md));
  the additive edition follows the same native-only design as the other runtime editions
  ([ADR 0030](decisions/0030-forge-and-engineering-lifecycle.md), [ADR 0022](decisions/0022-machine-global-workflow-contract.md)).
- Remote machines (Mac mini, Mac Studio) need their own measured install and verification; MacBook
  evidence never transfers.

## Forge posture (#1123 P3)

**Single-forge.** This edition installs one forge at a time. The native skill namespace (`skills/<name>/SKILL.md`) is flat: the three topics use
the same basenames for every forge, so a second install would overwrite the entry rather than add a
second one. The installer copies the selected forge's support scripts and leaves the previous
forge's renamed scripts in place. The P1 resolver guard refuses a repository that resolves to a different forge before any
forge CLI call, so the single-forge posture is safe; reinstall with
`--forge=<github|gitlab|gitea>` to switch. The issue #1123 P3 union-scripts + multi-entry layout is
therefore not used here.
