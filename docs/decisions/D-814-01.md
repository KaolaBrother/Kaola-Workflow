# D-814-01. Test custody replaces test order: the test author owns the test artifact

Date: 2026-07-26
Status: Accepted
Issue: #814

## Context

The implement-role split was organized by **order**. `tdd-guide` wrote tests and implementation in
one context (RED → GREEN → REFACTOR); `implementer` was the "no natural failing unit test" lane; and
choosing between them ran on a fuzzy testability heuristic duplicated in three independent wordings
across the planner profile, the adapt SKILL, and the init template.

Two problems followed from that shape.

First, **no rule on any surface forbade any role from modifying, weakening, or deleting a test.** The
grammar could say a test node ran first; it could not say who was allowed to touch the test
afterwards.

Second, and more fundamentally, order put the tests and the code they judge in the **same context**.
The agent implementing a behavior also authored the oracle that decided whether the behavior was
correct. That is the self-graded-oracle weak point 2025–2026 lab practice converged against —
grader independence ("the agent doing the work isn't the one grading it"), one context writing tests
and another writing the code to pass them, held-out fail-to-pass suites as the grading standard.

The repo already contained the structural answer, pointed at the gate side: a verifier never
provisions its own fixtures (an upstream writer provisions them inside its own write set), and an
inline gate reviewing its own writer-context is no gate. This decision applies the same principle to
the **writer** side.

## Decision

**Custody replaces order.** The axis is no longer *who runs first* but *who owns the test artifact*.

### 1. Role semantics

- **`tdd-guide` is the test author.** It authors tests from the acceptance surface (the plan's
  `## Acceptance` section when present, else the node brief and issue goal), proves them RED on the
  recorded baseline, and never writes production code. Its body states an **objective** — falsify the
  acceptance claims — not a style checklist.
- **`implementer` is the universal implementing role.** It takes over behavioral logic in addition to
  the six non-behavioral categories. It keeps **full read and execute access** to the tests — custody
  governs *write*, never read or run, so the iterate-to-green signal is untouched — and **zero write
  access to test paths**.

The **name `tdd-guide` is deliberately kept.** A rename or an added role touches a 22-path
registration surface keyed on no symbol of the file, for zero semantic gain. Repurposing the role in
place keeps registration stable.

### 2. Evidence tokens follow custody

Two rows of the D-433-01 registry change:

```js
'tdd-guide':   ['evidence-binding', 'RED', 'red_baseline'],
'implementer': ['evidence-binding', 'tests-green|regression-green|build-green|smoke-integration'],
```

- `tdd-guide` **loses `GREEN`**: a passing suite is a verdict about the implementation, and the author
  of a test is not the grader of the code it judges. GREEN authority moves to the gate side.
- `RED` **gains a receipt**, `red_baseline` — the baseline SHA the failure was captured on, checked
  against this open's recorded barrier baseline (the nonce is that baseline's 12-character prefix).
  Fail-on-baseline stops being a self-description and becomes a value the runtime checks, and a RED
  signature becomes non-transferable across reopens.
- `implementer` **drops `non_tdd_reason`** with the test-first/no-test dichotomy that justified it,
  and its verification-tier alternation gains `tests-green` for behavioral work.

### 3. The custody wall at freeze

A test-like path may appear only in a **test-author** node's `declared_write_set`. Any other role
needs a declared, hash-covered exemption in `## Meta`:

```
test_custody_exemption: <node-id> <path> — <one-line reason>
```

The reason is required — an unreasoned exemption is a rubber stamp, not a declaration — and the entry
must name a path that node actually declares, so an exemption can never be a wildcard. The
**synthesizer** is exempt for a path at least one of its `depends_on` legs also declares: by contract
it declares the union of its legs' write sets, so a leg's test path in that union is reconciliation,
not authorship. A test path no upstream leg declares is authorship and refuses.

The wall is **freeze-only**. `revalidateForResume` never applies it, so a plan frozen before this
rule existed still resumes byte-for-byte — a frozen plan that stops resuming is a silent break. The
runtime attribution floor still catches an undeclared test write in flight, so the resume path is not
left without teeth.

### 4. Shape stays planner reasoning

No selection prose is added. Behavioral work composes `tdd-guide` → `implementer` **serially with S1
evidence** (the implementer consumes the authored test files as its oracle — a named artifact
dependency), or **co-opens as a `parallel_safe` pair** when the acceptance surface already pins the
public interface, since then the write sets are disjoint by construction. The test author may itself
fan out over independent lenses (`cardinality` / `partitioned_all`). The equilibrium shifts toward
co-open as planning strengthens, with zero rule changes.

### 5. "The test is wrong" gets a typed route

`route-findings` infers `fix_role=tdd-guide` for behaviour, coverage, and test-defect findings — the
test author holds custody of the oracle, so routing such a finding to the implementer would either
strand it or invite the exact self-graded edit custody exists to prevent. The canonical finding
grammar's explicit `fix_role` still wins; the inference runs only on the free-prose fallback.

## Consequences

- The implementing context can no longer author, weaken, or delete the tests it will be graded by.
  Independence comes from **context isolation plus attribution**, not from hiding tests.
- Net prose *reduction*: the three-wording choose-guidance collapses into one custody sentence across
  the six routing surfaces and the init template, and the test-style rulebook leaves the role body.
  As model reasoning strengthens, incentive floors gain value while capability-tuned heuristics decay,
  so exactly one new mechanical wall is installed and checklists are removed.
- A legacy artifact carrying the retired tokens still closes (tolerated on read), and a legacy frozen
  plan still resumes.

## Explicitly rejected

- **A new `test-author` role name** — a rename touches the 22-path registration surface for no
  semantic gain.
- **A test-style rulebook in the role body** — every capability-tuned rule is a future straitjacket
  duplicated across ~7 runtime surfaces; objectives plus downstream judgment scale with the model.
- **Retiring the `RED` token** — fail-on-baseline is the one test-validity property with lab-grade
  evidence behind it. It survives precisely by moving from ceremony to receipt.
- **Secrecy (held-out tests the implementer cannot read)** — that requires a holder the workflow does
  not own, violating self-sufficiency, and it would destroy the iterate-to-green signal.
