# D-796-01. Task-description routing resolves to an issue before the claim; the `selection-evidence.md` sidecar gets a writer instead of losing its documented claim; `auto-bundle entry` is not renamed

Date: 2026-07-25
Status: Accepted
Issue: #796 (five reported routing/selection wording defects — this decision record covers the two
             that required a design choice, F2 and F5, plus a re-verification of a candidate rename,
             D3; F1, F3, and F4 were mechanical prose corrections with no alternative to weigh)
Related: #789 (`issue-scout` folded into `workflow-planner` — the source of F4's dangling profile
             citation and the reason the no-target survey is the only place F2's task-description
             resolution can live), `docs/architecture.md`, `docs/workflow-state-contract.md` (already
             document the sidecar's existence and header — D2 makes the planner profile match them
             instead of the reverse)

## Context

Issue #796 reported five wording defects in the agent-facing routing/selection prose layer (the
`next` routing topic, the `kaola-workflow-adapt` surfaces, and the `workflow-planner` profiles).
Three (F1, F3, F4) were pure reading-order or dangling-reference fixes with a single correct answer.
Two required a design decision, and a third candidate fix (renaming a contract token) needed
independent re-verification before being accepted or rejected.

## Decision

### D1 (F2) — a free-form task description resolves to exactly one issue before the claim

A free-form task description (the user describes the work but names no issue) now resolves to
exactly ONE issue **before** the claim and enters as an explicit target — it never enters the
no-target backlog survey. The description additionally reaches the `workflow-planner` verbatim as a
second dispatch field, `Binding scope:`, so the planner authors against the user's own words and not
merely a resolved issue's title. The resolution procedure is fail-closed: exactly one open issue
clearly matches → use it; none matches → file a new issue with the description verbatim as the body
and state the new number aloud; more than one plausibly matches, or the forge is unreachable → stop
and ask, never guess and never fall through to the survey.

**Why this is fact-determined, not a preference.** The issue's first fix-shape arm — "bind the
described task into the planner brief as the target directly" — is not implementable by prose alone:

- `cmdStartup` requires an explicit `--target-issue N` and refuses to pick one itself; a description
  carries no issue number, so nothing can be claimed.
- Every durable artifact this workflow produces is issue-keyed: the project folder
  `kaola-workflow/issue-N/`, the branch, `.roadmap/issue-N.md`, `issue_number`/`issue_numbers` in
  `workflow-state.md`, and the closure receipt that closes issue N.
- The only channel that carries free text today is `KAOLA_GOAL`, and the planner's contract makes it
  an explicit SOFT filter that priority ranking outranks — routing the description there would
  reproduce the exact reported defect (roadmap priority outranking the described task) rather than
  fix it.

So "resolve to an issue first" was forced by the shape of the system, not chosen among equally-valid
options.

**Rejected alternative:** binding the description into the planner brief as the target without first
resolving it to an issue number. Rejected as unimplementable for the reasons above, not merely
undesirable — there is no code path in this workflow that can claim, brief, or durably record work
that is not keyed by an issue number.

### D2 (F5) — give the `selection-evidence.md` sidecar a writer

`docs/architecture.md` and `docs/workflow-state-contract.md` already stated that the planner's
no-target survey docks its selection record to
`kaola-workflow/{project}/.cache/selection-evidence.md` with a `selection_mode: auto-bundle|single-issue`
header — that assignment was made when `issue-scout` was folded into the planner (#789), but the
planner's own profile was never updated to actually write it. The router's sentence claiming the
sidecar "remains present" was therefore true by accident, not by any writer honoring it.

**Decision:** the `workflow-planner`, in no-target survey mode only, now writes the sidecar after the
claim (never during the read-only survey, preserving the "the survey writes no state" invariant).
The router's sentence stays and is reworded to name the writer.

**Why, decisively, over the alternative:**

- Deleting the router's sentence instead would leave the two already-shipped docs (`architecture.md`,
  `workflow-state-contract.md`) wrong, and neither file is in any node's declared write set for this
  run — deletion was not executable here without opening a write-set finding for an unrelated pair of
  files.
- Keeping the sentence and making it true preserves, at zero further cost, everything already built
  against it: `probeSelectionEvidence` in all four `claim.js` editions, `closure_receipt.selection_evidence`,
  the `ARCHIVE_CACHE_SIDECAR_MD` archive carve-out, four walkthrough legs, and the `selection-evidence`
  needle in all five contract validators.
- It is mechanically free: `.cache/` already exists at claim time, and the sidecar is in the archive's
  sidecar exclusion set, so its presence or absence can never fail `verifyArchiveComplete`.

**Rejected alternative:** delete the sentence claiming the sidecar exists, since (at the time of the
finding) nothing wrote it. Rejected because it would have turned two already-correct, already-shipped
documents into stale ones, and would have required unwinding a probe, a closure-receipt field, an
archive carve-out, four walkthrough legs, and a needle in five validators — none of which were wrong,
only the planner's own profile was incomplete.

### D3 — `auto-bundle entry` is re-verified and deliberately NOT renamed

The `auto-bundle entry` contract token was re-verified independently against the tree rather than
accepted or rejected on the strength of the original report. It is carried by machine sites outside
the six routing surfaces this run edits: both `validate-workflow-contracts.js` copies, both Codex
contract validators, `templates/routing/required-blocks.js`, `scripts/test-route-reachability.js`,
both forge Codex walkthroughs, plus `README.md`, `docs/conventions.md`, `docs/architecture.md`,
`docs/api.md`, `docs/workflow-state-contract.md`, `docs/investigations/`, and other decision records —
roughly twenty files in total.

**Decision:** the identifier itself is not the misleading element and is not renamed. What misled a
reader working top-to-bottom was roughly 80 lines of bundle-shaped instruction sitting ahead of the
single-issue default — a reading-order and emphasis problem, which the F3 reordering fully resolves.
Every lane stays needle-preserving and the write-disjoint three-way antichain (`n2`/`n3`/`n4`) stays
legal.

**Rejected alternative:** rename `auto-bundle entry` to a name that does not read as a bundling
promise. Rejected for this run: it is a ~20-file contract-token migration, out of proportion to a
wording-defect fix, and not required to close any of the five reported findings — the reading-order
fix closes F3 without it.

**Residual, stated honestly:** the name still reads as a promise of bundling even after the emphasis
fix. That is a real, lower-severity wart, recorded as a filed follow-up rather than folded into this
run's scope.

## Consequences

- A user's free-form task description can no longer be silently outranked by the roadmap priority
  frontier: it is resolved to an issue and dispatched as an explicit target before any survey can run,
  with its exact wording preserved for the planner via `Binding scope:`.
- `docs/architecture.md` and `docs/workflow-state-contract.md` require no change — the planner profile
  was brought into alignment with what they already documented, closing the gap from #789 rather than
  reopening either document.
- The `auto-bundle entry` token remains stable across every routing surface, contract validator, and
  cross-reference that depends on it; a future contract-token migration for the naming wart is left as
  an explicitly out-of-scope follow-up, not silently absorbed here.
- Thirteen regression pins (`docs/decisions/` is not their home — they live in the five contract
  validators) now hold F1-F4 and the D2 sidecar binding in place; D1's task-description resolution and
  D3's non-rename are recorded here as the reviewable calls behind those pins.
