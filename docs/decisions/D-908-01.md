# D-908-01. Dispositions for the ten recorded coverage gaps: two pinned, one already closed, one rationale corrected, the rest open on record

Date: 2026-08-02
Status: Accepted
Issue: #908
Related: `scripts/test-claim-hardening.js` (the D1 five-leg suite, `:4745-4795`),
         `scripts/test-finalize-door.js` (`T8m(W6)`),
         `scripts/simulate-workflow-walkthrough.js` (`testClosureAuditScopedArchiveAmbiguousMatch903`),
         `scripts/kaola-workflow-closure-audit.js` (`archiveNameIsAmbiguous`),
         `scripts/validate-script-sync.js` (the byte-identity guard that is G4's actual mechanism)

## Context

#908 recorded five coverage gaps and five "also worth recording" notes as a durable list rather than
as work. Every one was re-measured against what shipped before anything was decided, and the
measurement changed three of the ten verdicts.

**One dating fact governs the first of those three.** #908 was filed at `2026-08-02T00:32:29+08:00`;
the bundle's repair commit `7350ba9c` landed at `00:43:33`, eleven minutes later. Gaps 1 and 3
therefore describe a mid-run snapshot, not the shipped tree. That is not a criticism of the record —
it is why a recorded gap is re-measured before it is worked.

The acceptance criterion that mattered was that **no production seam is added purely to make a test
possible**. It is satisfied, and not narrowly: measurement found that *none* of the ten needed one.
The two items closed here were closed with a CLI leg and an appended assertion arm; the export #908
declined (`missingArchiveSidecars` ×4, plus both forge `module.exports` blocks) was never what stood
between any of them and a pin.

## Decision

| item | disposition |
|---|---|
| **G1** — `archive_incomplete` + `missing[]` unpinned end-to-end | **Already closed before the issue was filed.** No work. |
| **G3** — full `cmdFinalize` in the worktree lane | **Closed.** Narrowed by measurement, then pinned. |
| **G5** — `archiveNameIsAmbiguous`'s count rule | **Closed.** Pinned by one CLI leg, no export. |
| **G2** (+ the adjacent **G2-b**) | **Open on record.** |
| **G4** — the Codex `closure-audit` copy | **Open on record.** |
| **Na / Nb / Nc / Nd** | **Open on record.** |
| **Ne** — the archive-sidecar exemption | **Settled, with its recorded rationale CORRECTED.** |

### G1 — already closed, and the proposed mechanism was the wrong one

`test-claim-hardening.js:4745-4795` (the D1 five-leg suite) drives `claim.js release --project <p>
--json` from a real linked worktree and asserts `result: 'refuse'`, `reason: 'archive_incomplete'`,
and `missing[]` naming the lost file; L1–L3 are the must-not-refuse controls. It is **mutation-proven
armed**: deleting the sidecar re-check from the emit produces exactly +5 failures, all of them the L5
leg, and nothing else moves.

The function #908 proposed extracting already exists in all four copies, and **no export was
needed**: the D1 legs use no export, no test hook and no production seam — they build a real worktree
topology and drive the shipped CLI. The record should point at that suite; the extraction cost #908
priced (four export sites, both forge ports needing the same symbol) was measured and is accurate,
and is simply no longer relevant.

### G3 — narrowed by measurement, then closed

The gap as written is too wide. The **self-host** worktree-lane full finalize *is* pinned
(`test-claim-hardening.js:4383-4407` runs the real transaction and asserts the archive destination on
disk). The genuinely uncovered cell was **consumer repo × worktree lane × full transaction** — the
one where the validation classification comes from `.cache/final-validation.md` rather than a chain
receipt, and where `T8m` stopped at `--check`.

Closed by appending `T8m(W6)` to `test-finalize-door.js`, reusing that test's existing fixture, `gh`
mock and recorded validation — assertions, not scaffolding — and running last, because finalize is
terminal and archives the folder every earlier assertion reads. Two mutants, and the second is the
one that proves coverage rather than merely arming: reverting to the pre-#832 archive destination so
a linked run archives into the invoking root fails **only** W6, two assertions, with every other leg
in the file green including T8m's own `--check` arm. The in-place legs cannot see that mutation,
because in-place *is* the invoking root.

### G5 — closed with a CLI leg and no export

Measured first: deleting `.filter(e => e.isDirectory())` from `closure-audit.js:220` leaves **both**
existing scoping scenarios green, so the four legs that were there armed nothing against this rule.
The discriminating fixture is a regular **file** in the archive band whose name matches the project's
archive-name shape — reachable from the CLI, whose scope envelope already carries both halves of the
answer. `archiveNameIsAmbiguous` stays module-private.

The leg pins both halves the miscount moves, because either alone lets a wrong implementation
through: the scope grows an `archive_name_ambiguous: true` it has no basis for, **and** the real
archive's finding is downgraded from `name_match` to `ambiguous_name_match` — a report disowning an
attribution that was never in doubt.

**Left unpinned deliberately:** the `catch (_) { return false; }` arm, reachable only through an
unreadable `kaola-workflow/archive/` directory. Not CLI-reachable without a permissions axis, and a
fixture that `chmod`s a directory the suite must then clean up is a hazard of its own. One branch,
fails safe.

### G2 and G2-b — open, and they are two different gaps

**G2 as written stays open, and its recorded reasoning holds.** With the run folder resident only in
a *second* linked worktree and `record` invoked from a first, the result is
`project_folder_missing`, and the hint names the two roots it searched rather than the one that has
the folder — which is the documented behaviour. A pin here asserts the absence of a route nobody
asked for.

**G2-b is not covered by that reasoning and is not in #908.** `otherProjectRoots` and the operator
hint it feeds need only **one** linked worktree: main plus a linked worktree both carrying the
folder, `record` run from main, and `other_candidate_roots` names the sibling and the hint fires. The
only pin on that field is the empty-array negative in a plain repo. So an ordinary topology has an
unpinned non-empty branch. Recorded here as a distinct item so it is not folded back into G2 and
dismissed with G2's argument.

### G4 — open, and byte-identity is the mechanism, not a placeholder

Confirmed exactly as recorded: the Codex walkthrough and the Codex contracts validator contain
**zero** references to `closure-audit`, and the GitLab and Gitea ports do have their own suites. A
mutated Codex copy passes the entire Codex chain and is caught **only** by `validate-script-sync.js`
byte-identity against canonical — which is mutation-proven armed (the mutation reds the sync
validator by name while the Codex walkthrough exits 0 at 184 spawns).

So this stays open with the mechanism named rather than closed with a fixture: byte-identity is a
guard, it is armed, and it is the correct one for a copy whose whole contract is "identical to
canonical". A Codex-side fixture would duplicate canonical coverage to defend a property parity
already defends. (One arithmetic correction to the issue: the canonical registry carries 37
closure-audit scenarios, 14 of them `903`-suffixed, not 13.)

### Na, Nb, Nc, Nd — open on record

- **Na** (the recorder command name spelled twice in the kernel's hints, with nothing keeping them in
  step) is **confirmed and worse than recorded**. The cross-copy axis is closed by byte-identity, so
  the four editions cannot disagree; the within-file axis is open, **no test asserts either hint's
  text**, and a **third** unbound spelling of the same invocation sits in the runner's own `usage()`.
  A renamed flag would leave three independent spellings free to disagree with nothing reading any of
  them. It is a drift *surface*, not an observed drift — recorded, not built.
- **Nb** (`record` in a self-host repo writes a file the gate never reads) is confirmed by
  measurement, and its own mitigation holds: the gate emits `chains_unverified`, not a false green.
  Pinning it would freeze "the write succeeds and the gate ignores it", which is a design answer
  still worth revisiting rather than one to nail down.
- **Nc** (a band-shaped directory in *no* repository still receives the `--output` JSON) is confirmed
  with a positive control — the same shape inside a repo exits 2 and writes nothing — and its
  mitigation holds: with no repository there is no durable archive to corrupt. Same caveat as Nb: a
  pin freezes the current answer, which the note itself argues is the right one.
- **Nd** (the `sync_required` arm does not probe its destination) is confirmed with a one-bit
  control, and is **sharper than recorded**: `--check` reports `ok: true` with `reasons: []` on a
  topology the transaction cannot complete — it exits 1 with a typed `archive_exception`, destroying
  nothing. That is a check/execute disagreement, the class #902 exists for, reached through a
  different arm. It stays open because pinning it would pin the *disagreement*: the design question
  (should `--check` probe the destination, or is a typed failure at execution the honest answer?)
  has to be settled before a pin can say which behaviour is correct.

### Ne — settled, and the recorded rationale was wrong about which pair

**Conclusion unchanged: the exemption is not too wide.** The five fixed `.cache/*.md` finalize
sidecars stay optional, and presence for exactly those names is re-added by `missingArchiveSidecars`,
whose pin is the mutation-proven D1 L5 leg.

**The rationale in the source comment is corrected.** It justified the exemption on the grounds that
"a normalized sidecar may legitimately differ from its source" — pointing at the `src ↔ dest` pair,
where the difference **cannot occur**: `copyDir` has no skip list, and both the `final-validation.md`
normalization and the terminal stamp run *before* the copy, so source and destination are equal by
construction at the moment the check runs.

A legitimate byte difference does exist, but on the **`mainLive ↔ dest`** pair — measured on the
`release` route from a linked worktree, where main's copy and the archive differ for an exempt
sidecar *and* for a non-exempt file alike. And byte tolerance there is not the exemption's doing at
all: it is a **caller** property, because that call site reads `.missing` only, deliberately and as
its own comment says. Removing the exemption would change nothing for either pair.

Recording the correction rather than only the conclusion, because the wrong rationale is the more
dangerous artifact: it is an argument a future reader would extend to a pair where it does not hold.

## Consequences

- Two items are closed with pins, one needed no work, one is settled with a corrected rationale, and
  six stay open **with their reasoning on record** rather than as an undifferentiated backlog. An
  item open because a pin would assert an absence, and an item open because a design question is
  unsettled, are different states and are recorded as different states.
- **No production seam was added**, and none was needed for any of the ten. The declined export is
  not what blocked anything.
- G2-b is a new item this review produced, not one #908 recorded. It is the one with a reachable
  route and no pin, and is the first of the open six to close if any do.
- Nd is a **design** question before it is a coverage question. A pin written today would freeze a
  check/execute disagreement as intended behaviour.
- One environment fact surfaced and is not chased here: a baseline `test-claim-hardening.js` run
  emitted `API rate limit exceeded` on stderr, so at least one scenario in that suite reaches the
  live forge API. It did not affect any verdict above — control and mutant emitted it identically,
  and the legs relied on set `KAOLA_WORKFLOW_OFFLINE=1` in their own spawn env — but that suite's
  result is not environment-independent. Recorded, not built on.
