# D-806-01. The inline lane is unbounded judgment, not a bounded lane with a justifier

Date: 2026-07-26
Status: Accepted
Issue: #806 (satisfied by #817, with its guardrail shape declined)
Relates: #817 (implemented), #805 (the repair dead-end #806 cites), #818 (the parallel disparity), D-818-01

## Context

Issue #806 asks for a **bounded inline-repair lane**: a sanctioned way for the
orchestrator to apply a small, fully-specified, machine-verifiable fix without a
dispatch. Its diagnosis is exact and is accepted in full — `CLAUDE.md` already said the
dispatch/inline choice was a judgment call with no justifier attached, while the shipped
mechanics offered no inline option for node-scoped writes. The stated principle and the
machinery disagreed. Its cost evidence is real: in the #796 run, a one-paragraph
reviewer-specified fix verifiable by an existing generator `--check` could only be applied
by abandoning the ledger path entirely, because the repair machinery dead-ended
(`repair_requires_replan` → `review_attempt_unresolved` → `evidence_generation_stale`).

Its acceptance criteria are now met, but by a different shape than it proposed.

| #806 AC | status |
|---|---|
| A documented lane, **or a reasoned rejection recorded in `docs/decisions/`** | this record, plus `docs/conventions.md` § *Execution mode is orchestrator judgment* |
| The lane is expressible in the executor | delivered — `--main-session-direct` is parsed for `close-node` and `close-and-open-next` and honored for **any** node, not just the finalize sink |
| `CLAUDE.md`'s economics guidance and the mechanics agree | delivered — that disagreement was #817's entire subject |

The dead-end that motivated the issue is separately fixed by #805.

## The disparity

#806 proposes the lane be **bounded**, with four guardrails: restricted to paths already in
the node's frozen `declared_write_set`; restricted to changes already specified by a durable
artifact; restricted to changes an existing mechanical check can prove; and **recorded as
`applied_inline: <reason>`**.

#817 shipped the opposite shape: execution mode is the orchestrator's per-unit judgment,
with *no* justifier, evidence line, or approval attached, and deliberately no mechanical
check validating the choice.

**Decision: #817's shape stands. The bounded-lane-with-justifier shape is declined.**

## Rationale

The two proposals agree on every constraint that catches a defect. They differ only on
whether those constraints should be re-expressed as the *entry condition of a special lane*.

Three of #806's four guardrails are already **unconditional** properties of the machinery,
binding identically whichever mode ran the unit:

- *Bounded by write set* — the exact-path barrier attributes every write to the node's
  frozen `declared_write_set` and refuses `write_set_overflow` outside it. It attributes by
  path, never by author, so it does not know or care who typed the bytes.
- *Bounded by verifiability* — the post-dominating gate nodes, the seeded `evidence-binding`
  nonce, and `record-evidence --verify` all still run.
- *Never for gate roles* — the gate-independence fence names `adversarial-verifier`,
  `code-reviewer` and `security-reviewer`, and is pinned in the contract validators.

Re-stating these as lane preconditions would not tighten anything. It would create a second
place where each rule is written — the failure class this project names *One Rule, One
Wording* — and a bounded lane's boundary is exactly the kind of thing that later gets
widened, whereas an unconditional barrier has no dial.

The fourth guardrail is the substantive disagreement. `applied_inline: <reason>` **is** the
justifier #817 subtracted, under a different name. A reason string the orchestrator must
produce *because* it chose inline re-creates the mandate one layer up: it makes inline the
marked case requiring an excuse, and dispatch the unmarked default requiring none. That is
the asymmetry #817 exists to remove. The distinction #806 wants preserved — an audit trail
showing who wrote it — is already kept, without a reason field: the compliance row records
`main-session-direct` versus `subagent-invoked`. **What** ran the unit is recorded; **why**
is not demanded.

This is the same disparity D-818-01 resolves for `local-fallback-tool-unavailable`, and it
resolves the same way: keep the fact, drop the excuse. The two records differ only in
direction — #818 wanted a status token retired that turned out to carry a real distinction,
#806 wants a reason token added that turns out to carry none.

Subtraction is the default (#808), and it applies here twice over: the lane #806 asks for
would add an entry condition, a reason field, and a fifth place to state four rules that are
already unconditional. The correctness net is the gate, not the dispatch — as #806 itself
argues.

## Consequences

- #806 is closed as satisfied by #817 and #805, with its guardrail shape explicitly declined
  under its own AC1 escape ("or a reasoned rejection recorded in `docs/decisions/`").
- There is no inline-repair *lane*, because there is no lane to enter: inline is an ordinary
  execution mode for any node, and the constraints #806 would have made lane preconditions
  bind unconditionally instead.
- A node the orchestrator runs inline closes with `--main-session-direct` and records
  `main-session-direct`. No reason accompanies it.
- The tighten-only boundary is unaffected: this record may never be cited to skip a typed
  gate, refusal, or barrier.
- If the audit trail ever proves insufficient in practice — a real incident where knowing
  *which* units ran inline was not enough and knowing *why* would have helped — revisit. The
  argument here rests on the mode alone being a sufficient record, not on justifiers being
  intrinsically wrong.
