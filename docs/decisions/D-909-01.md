# D-909-01. The closure-audit findings on this repository that no repair can clear

Date: 2026-08-02
Status: Accepted
Issue: #909
Related: `scripts/kaola-workflow-closure-audit.js` (`archive_summary_citation_missing`, the detector
         and its own adjudication comment at `:338-340`),
         D-796-01 (the issue whose stale label was the audit's other finding),
         #910 (the receipt-placement defect fixed in this same bundle, of which one finding here is
         the fossil)

## Context

#909's third acceptance criterion asks for one of two things: an unscoped `closure-audit` reporting
**zero findings**, or **every remaining finding a decision on record**. The first branch was measured
and is **unreachable on this repository**.

An unscoped audit reports **six findings across three classes**:

| class | count | disposition |
|---|---|---|
| `stale_in_progress_labels` | 1 | repaired — #796's label removed |
| `archive_content_incomplete` | 1 | repaired losslessly — `bundle-429-434`'s unique `sink-receipt.json` rehomed into its real sibling archive, then the residue directory removed |
| `archive_summary_citation_missing` | 4 | **this record** |

The third class is absent from #909's text entirely, so the issue's scope was short by four findings.
That class is report-only in both modes: `--execute` does not touch it, and no flag or repair
sequence exists that would. Three of the four are **bytes that no longer exist anywhere** — an
archive's `finalization-summary.md` cites a file, in its own archive, that the archive does not hold,
and the file is not recoverable from the working tree. Nothing can rebuild them, so the only thing
that can settle them is a decision. This is that decision.

The four were re-measured live for this record rather than inherited: the count and the split (three
real losses, one false positive) reproduce the `#901` implementer's original measurement exactly, so
no new citation drift has appeared since the detector shipped.

## Decision

**Accept all four findings as permanent, and record why each is unrepairable.** Do not delete or
rewrite the citing summaries: an archived `finalization-summary.md` is history, and editing one to
make a detector quiet would destroy the record that something was lost — which is the only remaining
evidence of the loss.

### 1. `bundle-440-441` → `.cache/chain-receipt.json` — REAL LOSS

The summary cites it **twice**, both times as positive evidence:

```
Chain receipt: `.cache/chain-receipt.json` (headSha: 05590e2f).
- chain-receipt: all 4 chains exit 0 — receipt at `.cache/chain-receipt.json`
```

That archive's `.cache/` holds a `sink-receipt.json` and node artifacts, and **no
`chain-receipt.json`**. The summary asserts a receipt at a path in its own archive and the bytes are
gone. Cited-as-evidence is what makes this the worst of the four: a reader of that archive is told a
four-chain green receipt exists and cannot check the claim.

### 2. `bundle-513-514` → `.cache/chain-receipt.json` — REAL LOSS

```
did not bite). HEAD-bound `.cache/chain-receipt.json` produced by `run-chains.js` over the final commit.
```

That `.cache/` holds 22 entries and **no receipt of any kind** — not even a `sink-receipt.json`. Same
shape as the first, one citation instead of two.

### 3. `issue-455` → `.cache/doc-updater.md` — REAL LOSS

Cited as Evidence in that run's compliance table:

```
| doc-updater | invoked | .cache/doc-updater.md (report) / docs diffs | |
| documentation docking | invoked | .cache/doc-docking.md | |
```

The archive holds `code-reviewer.md`, `dispatch-log.jsonl`, `doc-docking.md`, `planner.md`,
`sink-receipt.json` and `tdd-guide.md`. **`doc-docking.md` is present; `doc-updater.md` is not** —
and the table lists them as two distinct rows with two distinct producers, so **this is not a
rename**. Recorded explicitly, because "the file was renamed" is the first hypothesis a reader will
form and it is wrong.

### 4. `issue-891` → `.cache/chain-receipt.json` — FALSE POSITIVE

The sentence containing the token says where the receipt went:

```
The receipt landed at the repository-root `.cache/chain-receipt.json` because the run carried no
`--project` context, which is the path finalize probed and did not find.
```

That is prose *about* a path, not a claim of presence in the archive — and the detector's own comment
already adjudicates this exact shape:

> The fourth cites a receipt while naming, in the same sentence, the repository-root path it actually
> landed at — a prose mention is not a claim of presence, and no structural rule separates the two …
> So this reports the citation and the operator adjudicates; it is never a verdict and never repairs.

**Recorded here rather than left implicit, and worth reading twice: this finding is the fossil of
#910.** The receipt landed at the repository root for want of `--project` resolving across working
trees — the defect fixed in this same bundle. The audit has been pointing at that bug in the archive
record since the receipt class shipped, and nobody read it as a bug report. A report-only class whose
false positive is a true record of a different defect is worth more than a class that could be made
to go quiet.

## Consequences

- **"Zero findings" is not the acceptance bar for this repository and should not be re-adopted as
  one.** Four findings stand permanently. A future audit reporting exactly these four is **clean**;
  a fifth is new drift and is the thing to look at.
- #909 closes on its second branch, saying so, rather than on an unreachable first branch.
- The three real losses are not repaired and not repairable. No `--execute` run, and no hand edit of
  an archived summary, will change that, and attempting the latter would trade a recorded loss for a
  silent one.
- The detector's precision is unchanged and was not tuned to fit this record: it flags four, three
  are real, and its one false positive is documented at the site. Narrowing it to exclude the
  `issue-891` shape would need a structural rule separating a prose mention from a presence claim,
  which does not exist — and would have suppressed the only durable trace of #910.

## Alternatives considered

- **Reconstruct the missing receipts.** Impossible for the two `chain-receipt.json` citations: a
  receipt binds a `headSha` and a `codeTreeHash` at a commit whose chains were run at that moment.
  Anything produced now would be a fabrication wearing a receipt's shape, which is strictly worse
  than an honest gap.
- **Edit the archived summaries to remove the citations.** Rejected outright. It makes the detector
  quiet by destroying the evidence, and an archived `finalization-summary.md` is a historical record
  this project does not rewrite — the same reason a legacy receipt carrying a retired field is kept
  verbatim.
- **Suppress the class, or add a per-archive waiver file.** Rejected as machinery derived for a
  failure class of exactly four instances, none of which will recur (the citing runs are closed).
  Add only what an observed failure demands; a decision on record is what the acceptance criterion
  already offers, and it costs nothing to maintain.
