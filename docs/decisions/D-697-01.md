# D-697-01 — Extend D-547-01 validation_command for schema 2 and execute it with a deterministic local runner

- **Status:** accepted. **Amended 2026-08-02 (issue #905)** — see § "Amendment (2026-08-02): the
  `--keep-output` carve-out". The default retention posture is unchanged; one opt-in exception was
  added.
- **Date:** 2026-07-15
- **Context:** issue #697
- **Extends:** D-547-01 for newly authored schema-2 plans; legacy D-547-01 behavior is preserved

## Context

D-547-01 established one hash-covered `validation_command` recorded at plan freeze. For existing
plans it is reader-only metadata used by record-once/freshness behavior; it does not mandate a
runner, timeout, repeated execution, or environment semantics. Reviewer contract 2 needs comparable
current-candidate validation vectors and therefore needs bounded execution policy and deterministic
command identity.

Adding a second namespaced command key would create two authorities that could disagree. Reusing the
old key without an explicit version boundary would retroactively change frozen-plan semantics and
bytes.

## Decision

Extend the existing `validation_command` namespace for plan schema 2. Do not add a second command
field. Add hash-covered sibling fields:

- `validation_cwd` — normalized repository-relative path, default `.`;
- `validation_repetitions` — integer `1..5`, default `1`;
- `validation_pass_rule` — exactly `all`;
- `validation_timeout_minutes` — integer `1..120`; and
- `validation_env_allowlist` — sorted, duplicate-free shell identifiers, default empty.

A schema-2 code-producing plan requires both `validation_command` and
`validation_timeout_minutes`. Unknown/duplicate policy fields, path escape, non-all pass rules,
invalid bounds, or noncanonical environment keys refuse freeze.

Preserve D-547-01 exactly for a verified contract-1 plan. `parseValidationPolicy` maps it to:

```text
command = existing validation_command or null
cwd = .
repetitions = 1
pass_rule = all
timeout_minutes = null
env_allowlist = []
runner_required = false
source = legacy-d547
```

This mapping does not rewrite legacy plan or journal bytes and imposes no new execution/timeout
semantics. `validation_test_consumes` retains its existing freshness-band role.

Implement a forge-neutral, four-edition byte-identical
`kaola-workflow-validation-runner.js`. It starts child execution from a scrubbed environment,
injecting deterministic/platform-minimum keys plus the frozen allowlist. `command_id` binds exact
command bytes, normalized policy, secret-safe effective-value digests, Node/shell/simple-command
executable realpath-mode-version identities, and relevant lock/toolchain identities. The validation
vector separately binds candidate identity and every repetition's pre/post candidate digest. Raw
allowlisted values and raw child output are not persisted. *(Amended 2026-08-02: child output is not
persisted **by default**, and one opt-in exception now exists — see the amendment section below.
Allowlisted values are unchanged and are never persisted.)*

Every repetition binds pre/post candidate digests, exit/signal/timeout, output digests, and normalized
failure signature. Reduction is:

- `pass` only when every comparable run exits zero and the candidate stays unchanged;
- `fail` only when every comparable run exits nonzero with one stable failure signature and no
  mutation/signal/timeout; and
- `inconclusive` for mixed results/signatures, timeout, signal, candidate mutation, unresolved or
  incomparable identity, or any other case.

`vector_id` excludes audit timestamps and addresses deterministic semantic fields;
`receipt_sha256` binds the complete durable receipt including audit time. Inherited obligations are
`{command_id, required_pass_vector_id}` and may not be silently dropped or changed.

The opt-in local Claude/Codex qualification command records contract/profile/context identities and
invariant-class outcomes through mockable process adapters. It does not compare natural-language
finding equality and is not an external completion authority.

## Amendment (2026-08-02): the `--keep-output` carve-out

- **Date:** 2026-08-02
- **Context:** issue #905
- **Decided by:** the repo owner, in conversation. The alternative on the table — always-on inline
  retention of the failure preimage in the receipt — was rejected in favour of this.

**What was observed.** The non-persistence rule above, read as absolute, makes a red receipt
undiagnosable. A real failing run was captured: `outcome: fail`, `reduction_reasons: []`, and **zero
bytes** of the child's output anywhere — nothing on the runner's terminal, nothing on disk, nothing
in the receipt. The preimages were proven alive at hash time (`normalizeFailureSignature` returns
`{normalized, digest}` and the caller binds both, reading only `.digest`; all three digests were
re-derived out of band and matched). So the runner *had* the diagnosis and discarded it, and the
whole diagnosis in that case fitted in 165 bytes. That is a real cost that the rule as written
imposes on every red run, and nothing in the original derivation weighed it: the rule was written to
keep secrets out of receipts, not to make failures unreadable.

**The carve-out.** `run --keep-output <dir>` retains the child's raw stdout and stderr, and only
under all four of these conditions:

1. **Opt-in.** Absent the flag, nothing is retained and behaviour is byte-identical to the original
   decision. There is no default destination and no environment variable that turns it on.
2. **Caller-named destination.** The operator names the directory. This is the consent mechanism —
   the flag *is* the choice — which is why a path inside the operator's own tracked tree is
   permitted: refusing it would override an explicit instruction about their own repository's
   history, and that is a value call, not the runner's.
3. **The durable archive band is refused.** A destination resolving inside
   `kaola-workflow/archive/**` exits 2 before the child runs. That band holds closed evidence, and a
   stray directory there reads to the closure audit as a phantom project missing its state file —
   permanent drift with nothing to repair. This is not a value call; it is a defect the runner
   already refuses on `--output` for the same reason.
4. **Receipt identity is untouched.** No receipt field is added and no digest moves. Retention is a
   side channel, never part of validation identity, which is precisely what keeps this an exception
   to the persistence rule rather than an amendment to the identity rule.

**What is deliberately unchanged.** The default posture, and the reason for it. There is still **no
secret redaction** — `normalizeOutputText` redacts absolute paths and nothing else — and
`kaola-workflow/**/.cache/` is a **tracked** path in this repository, so unconditional retention
would put child output into permanent git history. Both facts stand; they are exactly why retention
is opt-in, refuses to overwrite, and states the exposure in `usage()` where the operator reads it
rather than in a document they may not. Raw *allowlisted environment values* remain unpersisted with
no exception: their digests are the whole mechanism by which a secret influences command identity
without appearing anywhere, and nothing observed argues against that.

**Alternatives considered and rejected**, both measured before the choice:

- **Always-on inline retention of the normalized failure signature in the receipt.** Rejected: it
  persists child output on every run with no operator choice at all, and it is the direction with the
  most exposure for the least control.
- **Widening the receipt to carry a retention path or the output itself.** Rejected: `audit` is the
  only determinism-safe home for such a field, and any other placement re-keys every `vector_id`
  once and is unbounded to 16.78 MB. `--keep-output` is the only one of the three directions with
  zero effect on receipt hash properties, and that is why it was chosen.

## Consequences

- There remains one frozen validation command authority across plan versions.
- Contract-1 behavior and bytes remain stable; contract 2 gains deterministic comparable vectors.
- Secrets influence command identity through digests without appearing in receipts.
- Timeout, signal, flake, mutation, and toolchain ambiguity fail closed as `inconclusive`.
- Validation is owned and local; no hosted pipeline is required as a plan or Finalization gate.

## Alternatives considered

- **Add `review_validation_command` or another namespace.** Rejected because two command fields can
  disagree and weaken freshness/comparability.
- **Retrofit runner semantics onto D-547-01 plans.** Rejected because it changes a frozen public
  contract and could brick resumable work.
- **Use an external service as the validator.** Rejected because completion must not depend on an
  authority the workflow does not own.
