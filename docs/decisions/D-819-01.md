# D-819-01. A structural gap-vs-deliverable classifier, not a force-reset flag, repairs `substitute-role`

Date: 2026-07-27
Status: Accepted
Issue: #819
Related: `scripts/kaola-workflow-adaptive-node.js` (`runSubstituteRole`, `classifyEvidenceBody`,
         `hasEvidenceBodyBelowHeader`, `codexTaskNameForNode`, `buildDispatch`) + its 3 ports
         (`plugins/kaola-workflow/scripts/kaola-workflow-adaptive-node.js`,
         `plugins/kaola-workflow-gitlab/scripts/kaola-gitlab-workflow-adaptive-node.js`,
         `plugins/kaola-workflow-gitea/scripts/kaola-gitea-workflow-adaptive-node.js`),
         `scripts/kaola-workflow-adaptive-schema.js` (`DELEGATION_OUTCOME_VOCABULARY`, untouched),
         issue #798 (the original `substitute-role` channel this repairs),
         issue #611 (the `delegation_outcome` typed evidence shape this reads but does not widen)

## Context

A Codex run recorded a `code-explorer` node self-persisting a `capability_gap` return (it could not
read the repository under the dispatch it was given) and then wedging: `substitute-role` refused with
`substitute_node_closed`, and the only thing that moved the run forward was an orchestrator hand
`apply_patch` reverting the evidence body to a bare seeded binding. A second, related residue in the
same run: a `--to-role code-explorer` call issued against a node already frozen `code-explorer`
recorded a substitution row that redirected nothing.

The initial framing — captured in this issue's own `## Design` section and repeated in this decision's
first-drafted brief — was that the fix was narrow: teach the guard to recognize a column-0
`capability_gap:` key as "this body is a gap, not a deliverable" and let the swap through. Investigation
(`n1-surface`) measured that framing against the actual run and against production code before any line
was written, and both measurements came back different from what was assumed.

**First correction.** The real gapping role's evidence, read from the session JSONL, carried **no**
column-0 `capability_gap:` line at all — the token appeared only nested inside an indented `outcome:`
value, which a classifier keyed on the column-0 key would not have matched. What the role *did* write,
unprompted, was a column-0 `delegation_outcome: capability_gap` line — a token this codebase already
parses (`parseDelegationOutcome`) but had never taught `substitute-role` to read.

**Second correction, the more consequential one.** The measured blocker was broader than "a gap body
blocks the swap." `seedEvidenceFile`'s fresh seed writes an `<!-- <token>: paste <token> here -->`
guidance comment above every stub token, for **all 18 manifest entries** (15 agent roles + 3
`kind: built-in`), and the pre-existing `hasEvidenceBodyBelowHeader` predicate counted any non-blank,
non-valueless-token line — including that comment — as a recorded body. The production seed alone, with
no dispatch and no gap, already refused `substitute_node_closed` on every freshly-opened node. A fix
that only recognized a gap marker would have passed the acceptance criteria on a hand-written fixture
and left the real defect live, because the scaffold blocks the swap before any marker is ever written.

## Decision

### 1. A structural three-way classifier, not a force-reset flag

`classifyEvidenceBody(content, role)` returns `'seeded' | 'capability_gap' | 'deliverable'`, replacing
the single boolean body check inside `runSubstituteRole`. `'capability_gap'` requires **both** halves,
and the second is load-bearing: a typed, column-0-anchored marker (**both** forms are accepted —
`capability_gap: <value>`, the return form the role profiles mandate, and `delegation_outcome:
capability_gap`, the form the real gapping role actually wrote), **and** no non-empty value for any
content-bearing token the role's own `ROLE_TOKEN_REGISTRY` row demands — checked with the identical
value-presence regex `checkEvidenceShape` uses, so the two gates can never disagree about what "a token
carries a value" means. A role can therefore only be classified as gapped by withholding its whole
deliverable; stamping the marker over real findings still classifies `deliverable`, and the swap still
refuses.

The alternative on the table — a `--reset-evidence` opt-in flag that force-clears any body — was
rejected on integrity, not convenience. A flag with no structural check behind it converts the guard
into a speed bump: an orchestrator that meets `substitute_node_closed` would reflexively re-run with the
flag and can destroy real, undelivered work exactly as readily as a genuine gap. It also fails the
guard's second clause outright — it would no longer refuse a genuine deliverable, only complain once.
The classifier gives both properties (unblock a genuine gap; still refuse a genuine deliverable) with
**no override path at all**, which is the strictly stronger posture, at the cost of one extra classifier
function instead of one flag parse.

The scaffold blocker is repaired separately, inside `hasEvidenceBodyBelowHeader` itself (still the
`'seeded'` test `classifyEvidenceBody` calls first): a whole-line HTML-comment line is no longer counted
as a body, anchored at both ends so a line that merely *starts* with a comment and then carries prose
still counts as one. The alternative considered and rejected here was matching only the literal
`<!-- token: paste token here -->` string the seeder emits — narrower, but the seeder emits at least
four distinct comment shapes (per-token guidance, the `domain_outcome` vocabulary note, the
routable-anchor note, the upstream-read instruction), and a literal-matched subset would silently
re-wedge whichever role's seed happens to use a shape the literal missed.

### 2. Who owns the atomic reset, and why no new subcommand exists

**`substitute-role` itself owns the reset** — no new subcommand, no new flag. The reset runs inside the
existing subcommand's commit phase, only when the body classified `capability_gap`, and reuses the
existing `seedEvidenceFile(..., forceRotate=true)` primitive (tmp + fsync + rename via
`writeFileAtomicReplace`) rather than adding a second writer. A standalone `reset-evidence` subcommand
was considered and rejected: it would be a general-purpose "discard a node's evidence" tool — a strictly
larger and more dangerous capability than this defect needs — and it would have to join five separate
in-file registration lists (dispatch switch, `SPLIT_GUARDED_SUBCOMMANDS`, `REPLAN_GUARDED_SUBCOMMANDS`,
the usage block, `OPERATOR_HINT_REGISTRY`), each a place to ship an unguarded mutator. `substitute-role`
is already a member of both guard sets, so the reset inherits the full worktree-authority-split guard
and the scheduler lock with zero new registration — and, structurally, the reset can never be invoked as
a free-standing wipe: it is reachable only after P1–P4 have already proven a valid in-kind superset
target exists.

The reset **preserves** the binding nonce; it does not rotate it. The nonce is the barrier baseline's
SHA prefix (`readNonce`), so rotating it would re-record the baseline mid-node and silently absorb
anything the gapped role wrote into the "before" snapshot — laundering an out-of-set write through the
very repair meant to keep the run honest. It would also make the re-dispatched role's evidence refuse
`evidence_stale` at close, trading one wedge for another. `substitute_evidence_reset_failed` is the one
new refusal code covering both ways the reset can fail (no resolvable nonce; the atomic re-seed itself
reports failure), writing no record in either case.

### 3. Task identity derived from the dispatch target, under a byte-identity constraint

The Codex task name is now derived from the role that will **actually be dispatched** (the resolved
`agent_type`) rather than from the plan's frozen `role` cell. `codexTaskNameForNode` gains an *optional*
second parameter; every existing one-argument call site is unaffected, and `buildDispatch` resolves the
substitution before computing the name.

This had to respect a hard byte-identity constraint: with no substitution on record, an unsubstituted
node's dispatch card — `codex_task_name` included — must be **byte-identical** to the pre-#819 card,
because `scripts/simulate-workflow-walkthrough.js:21452` hard-asserts `d.codex_task_name ===
'n1_tdd_guide'` for an unsubstituted node, and that assertion lives outside every write set this issue
touches; breaking it would have been an unrecoverable write-set overflow, not a repairable regression.
The derivation was proven byte-identical over all 18 roles in the manifest × 3 model tiers × 4 dispatch
contexts (293 comparisons, 0 mismatches, key order included), and the walkthrough assertion itself was
run — not merely inferred as preserved.

### 4. What P5 still guarantees, and what it no longer guarantees

**Still guarantees.** `substitute-role` never proceeds past a deliverable: the ledger-status arm is
untouched and runs first, so a `complete`/`n/a` node still refuses regardless of its body; a body
carrying real, non-empty content for any required token is `deliverable` regardless of what marker is
stamped alongside it, and the swap refuses `substitute_node_closed`; there is no flag, environment
variable, or argument that overrides either arm.

**No longer guarantees.** P5 no longer guarantees the evidence file is byte-untouched across a
substitution: on the `capability_gap` classification the body is destroyed and re-seeded, irreversibly
and with no backup, so a role that jotted partial notes and then gapped loses those notes along with the
gap marker. The predicate has moved from a one-line emptiness test to a classifier whose correctness now
depends on the marker vocabulary and the role's own token registry rather than on a single boolean — the
deliberate price of making a genuine gap unblockable at all.

## The honest history of the marker decision, recorded rather than smoothed over

The reasoning that originally motivated keying the classifier on a column-0 `capability_gap:` key —
"it's already a shipped, cross-edition evidence-file token" — was **measured false** against the run
this issue cites, not merely revised for elegance. It is shipped as the mandated *return* form in the
role profiles, not as anything any profile instructs a role to write into the evidence file, and the
real gapping role's evidence carried no such column-0 line. A classifier keyed on it alone would have
classified the observed defect's own evidence as a deliverable and refused — the fix would not have
fixed the failure it was built to fix.

A second premise in the same original framing — "stable across all four editions" — was also measured
false for that key's literal phrase: three of four `.toml` role-profile editions ASCII-normalize the em
dash in `capability_gap: <missing capability> — <required action>` to a plain double-hyphen, so a check
keyed on the full phrase (rather than the bare column-0 key) is not cross-edition stable and would behave
differently on Codex than on Claude.

The conclusion the original framing reached — key on `capability_gap:` — survived, but only as one of
two markers, not the sufficient one; the *reasoning* that justified it as sufficient did not survive.
That is exactly why `classifyEvidenceBody` accepts **both** typed markers rather than either alone: the
column-0 `capability_gap:` key is retained because it costs one regex and is the form the profiles
already mandate, so a role that does write it is still served, but the column-0 `delegation_outcome:
capability_gap` line is what the classifier actually needed to unblock the run on record — it is the one
form measured to have been written, unprompted, by a real role hitting this real defect.

The scaffold-comment repair to `hasEvidenceBodyBelowHeader` was a late discovery in the same
investigation, not part of the original framing at all: the production seed alone — no marker, no
dispatch — was already tripping the guard for every one of the 18 manifest entries (15 agent roles + 3
`kind: built-in`), which made the narrower marker-only fix insufficient on its own regardless of which
marker it recognized.

## Explicitly rejected

- **A `--reset-evidence` opt-in force-clear flag** — converts a guard into a speed bump; loses the
  "still refuses a genuine deliverable" property entirely. See §1.
- **A standalone `reset-evidence` subcommand** — a strictly larger, unnecessarily general capability
  that would need to join five in-file registration lists on its own. See §2.
- **Keying the classifier on the column-0 `capability_gap:` key alone** — measured to not fire on the
  only real gap body on record (see "The honest history," above); kept as one of two accepted markers,
  never as the sole one.
- **Matching only the literal `<!-- token: paste token here -->` seed-comment string** — narrower than
  the whole-line-comment tolerance actually shipped; the seeder emits at least four distinct comment
  shapes, and a literal match would silently re-wedge whichever role's seed uses one it missed.
- **Teaching the role-profile prose (~56 surfaces: `agents/*.md` plus three `.toml` editions each) to
  emit a column-0 `capability_gap:` line into the evidence file itself.** This would upgrade recovery
  from best-effort to deterministic, but it is a profile-prose scope expansion this issue's write sets
  do not cover, and the classifier is fail-closed without it — a gap body in neither typed form degrades
  to exactly today's pre-#819 behavior (`substitute_node_closed` → consent halt), never to a wrong
  success. Left as a named, unabsorbed residual rather than built.
- **Rotating the nonce inside the atomic reset** — would re-snapshot the barrier baseline mid-node
  (laundering anything the gapped role wrote) and would make the re-dispatched role's own evidence
  refuse `evidence_stale` at close. The reset preserves the nonce instead. See §2.

## Consequences

- A self-persisted `capability_gap` body — in either typed form — now unblocks `substitute-role`; the
  production seed scaffold no longer blocks it on its own for any of the 18 manifest entries (15 agent
  roles + 3 `kind: built-in`).
- `--to-role <the frozen role>` now refuses `substitute_self_noop` instead of silently recording a
  no-op row, including the revert case (an active record to another role, then back to the frozen one).
- A substituted node presents a fresh Codex task identity; an unsubstituted node's dispatch card is
  unchanged, proven rather than assumed.
- The close-time gate is unchanged by design: `delegation_outcome: capability_gap` stays outside
  `DELEGATION_OUTCOME_VOCABULARY`, so a gap is read at substitute time and still refused at close time —
  a gap may never close a node, only unblock a re-dispatch of it.
- Two residuals are named and deliberately left unabsorbed by this issue: teaching role-profile prose to
  emit a deterministic evidence-file marker (see "Explicitly rejected," above), and `reopen-node`'s
  task-identity collision on a re-dispatched COMPLETE node (it rotates the nonce but not the identity;
  the derivation in §3 composes with a later attempt-ordinal suffix without disturbing byte-identity, so
  fixing it later does not require revisiting this decision).
